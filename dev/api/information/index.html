Experiments and exact value of information

The definitions on finite problems. The same functions, called with a method or a study, estimate these quantities from a sample: see Sample-based analysis.

Experiments

DecisionAnalysis.Experiment — Type
Experiment(likelihood; signals, states=nothing, cost=0, atol)
Experiment(k::FiniteKernel; cost=0, atol)

An information source over a finite state space. likelihood[z, θ] = P(z | θ): rows are signals and columns are states, so every column sums to one (exactly for Rational entries, within atol otherwise); a matrix that is not column-stochastic throws InvalidExperimentError. signals labels the rows (default :z1, :z2, ...). states, when given, labels the columns and is checked against the payoff table of any problem the experiment is used with; without it only the number of states is checked. cost is the price of running the experiment, in payoff units; it is used only by enbs.

The second form takes a kernel of FiniteKernels from states to signals; its kernel_matrix is already laid out signals-by-states. Several-axis spaces are labelled as in FiniteBelief.

julia> e = Experiment([4//5 1//5; 1//5 4//5]; signals=[:negative, :positive]);

julia> size(e.likelihood)
(2, 2)

DecisionAnalysis.gaussian_experiment — Function
gaussian_experiment(means::AbstractVector{<:Real}, sd::Real; states=nothing,
                    bins=400, width=8, cost=0)

A measurement with normally distributed error, as a finite Experiment: under state θ the observation is Normal(means[θ], sd), and the signal is the bin of a regular grid that the observation falls in. The grid has bins bins and runs from minimum(means) − width × sd to maximum(means) + width × sd.

likelihood[z, θ] is the normal density at the midpoint of bin z, normalised so that each column sums to one (midpoint rule; the mass beyond width standard deviations is below 1e-14 at the default). The experiment is therefore a discretised version of the continuous measurement, and its evsi approaches that of the continuous measurement as bins grows; check convergence by doubling bins. The entries are Float64, so the result is not exact arithmetic. sd must be positive (a measurement without error reveals the partition of the states by their means; use evppi).

This is the experiment behind "learning by doing" with measurement error: means is the row of the payoff table of the action that is tried, and the observed outcome updates the weights of the hypotheses (Runge, Converse and Lyons 2011).

julia> e = gaussian_experiment([0.0, 1.0], 0.5; states=[:low, :high], bins=200);

julia> p = DecisionProblem(PayoffTable([:a, :b], [:low, :high], [1.0 0.0; 0.0 1.0]),
                           [0.5, 0.5]);

julia> round(evsi(p, e); digits=3), evpi(p)
(0.341, 0.5)

DecisionAnalysis.bayes_invert — Function
bayes_invert(prior::FiniteBelief, experiment::Experiment) -> BayesianInversion
bayes_invert(prior::AbstractVector, experiment::Experiment) -> BayesianInversion

Bayes' rule for a prior over states and an experiment: the signal marginal P(z) = Σ_θ p(θ) L[z, θ] and, for every signal, the posterior P(θ | z) = p(θ) L[z, θ] / P(z).

A signal of probability zero has no posterior. Its entry in posteriors is nothing; it is never NaN and never an arbitrary distribution. (The value of information does not need the division at all; see value_with_information.)

julia> prior = FiniteBelief([:low, :high], [3 // 5, 2 // 5]);

julia> test = Experiment([4//5 1//5; 1//5 4//5]; signals=[:negative, :positive]);

julia> inv = bayes_invert(prior, test);

julia> inv.marginal
2-element Vector{Rational{Int64}}:
 14//25
 11//25

julia> probabilities(inv.posteriors[2])
2-element Vector{Rational{Int64}}:
 3//11
 8//11

DecisionAnalysis.garble — Function
garble(experiment::Experiment, G; signals, cost=experiment.cost, atol) -> Experiment

The experiment obtained by passing the signal of experiment through the noisy channel G, where G[z′, z] = P(z′ | z): rows are the new signals, columns the old ones, and every column sums to one. The likelihood of the result is G * L. By Blackwell's theorem a garbled experiment is worth no more than the original to any decision-maker with a single prior; see evsi.

G that is not column-stochastic, or has the wrong number of columns, throws InvalidExperimentError.

DecisionAnalysis.is_garbling_of — Function
is_garbling_of(e′::Experiment, e::Experiment; atol, optimizer=nothing,
               rounding_tol=(1e-8, 1e-10, 1e-12)) -> Union{Matrix,Nothing}

Whether e′ is a garbling of e, that is, whether e′ is less informative than e in Blackwell's order. Returns a witness: a column-stochastic matrix G with G[z′, z] = P(z′ | z) and G * L_e = L_e′, or nothing when there is none.

For Rational likelihoods the default atol is zero, the test is the feasibility programme of garbling_model, and the answer is exact, with a witness whose product reproduces L_e′ entry for entry. For floating-point likelihoods the test is the programme of deficiency: a witness is returned when deficiency(e, e′) is at most atol (default 1e-8).

This is garbling_result(e′, e; ...).witness. With a floating-point optimizer on rational likelihoods a matrix that is returned has still been verified exactly, but a nothing is then numerical; garbling_result says which.

DecisionAnalysis.garbling_result — Function
garbling_result(e′::Experiment, e::Experiment; atol, optimizer=nothing,
                rounding_tol=(1e-8, 1e-10, 1e-12), separating=true) -> GarblingResult

Decide whether e′ is a garbling of e (whether e′ is less informative than e in Blackwell's order) and say how sure the answer is; is_garbling_of returns only the witness.

For Rational or integer likelihoods and atol = 0 (the default for them) the feasibility programme of garbling_model is solved. A witness, whatever found it, is returned only after it has passed the exact check; with a floating-point optimizer it is first rounded and cleaned up (negative entries to zero, columns renormalised), and ExactVerificationError is thrown if the optimiser reports a garbling and the cleaned matrix is not exactly one. When the answer is no, the programme of separating_payoff_model is solved as well and the result carries the separating decision problem (see GarblingResult); separating = false skips that second programme when only the yes or no is wanted and the first programme was solved exactly. A "no" from a floating-point optimiser is exact once a separating problem passes the exact check, and numerical, and marked so, otherwise.

Otherwise (floating-point likelihoods, or atol > 0) the programme of deficiency_model is solved and the pair counts as a garbling when the deficiency is at most atol (default 1e-8 in floating point); the answer is numerical.

optimizer and rounding_tol are those of solve_program.

DecisionAnalysis.GarblingResult — Type
GarblingResult

What garbling_result returns. Fields:

  • is_garbling: whether the first experiment is a garbling of the second.
  • witness: when it is, a column-stochastic matrix G with G[z′, z] = P(z′ | z) and G * L_e = L_e′; otherwise nothing.
  • exact: whether is_garbling is an exact statement. A true with exact set carries a witness that was checked in exact arithmetic (G nonnegative, columns summing to one, G * L_e == L_e′ entry for entry). A false is exact by the default route or with an exact optimiser, and numerical (to the tolerance of the optimiser) with a floating-point optimiser. Every answer for floating-point likelihoods, or with a nonzero atol, is numerical.
  • route: the route that solved the programme (see ProgramSolution).
  • separating: when the answer is an exact "no", a separating decision problem: a DecisionProblem on the states of the experiments, with one action per signal of the first experiment and a uniform prior, in which the first experiment is worth strictly more than the second (evsi(separating, e′) > evsi(separating, e), checked in exact arithmetic before it is returned). By Blackwell's theorem such a problem exists exactly when the first experiment is not a garbling of the second, so it is the reason for the "no" in a form that can be inspected: a decision-maker who would rather have the first experiment. It is the content of the file written by export_not_garbling_witness. nothing when the answer is yes, when it is numerical, or when separating = false was passed.

DecisionAnalysis.deficiency — Function
deficiency(e::Experiment, e′::Experiment; optimizer=nothing, rounding_tol=(1e-8, 1e-10, 1e-12))

Le Cam's deficiency of e with respect to e′: how far e is from being able to simulate e′,

δ(e, e′) = min_G max_θ TV(G · L_e[·, θ], L_e′[·, θ]),

the minimum over column-stochastic matrices G (garblings of e) of the largest total-variation distance, over states, between the garbled likelihood and the likelihood of e′. Total variation is half the ℓ¹ distance, as in total_variation.

δ(e, e′) = 0 exactly when e′ is a garbling of e. It is not symmetric, and most pairs of experiments have both δ(e, e′) > 0 and δ(e′, e) > 0: they are incomparable in Blackwell's order. The deficiency still bounds the value gap: for a payoff table with range B (largest minus smallest payoff), the value of acting on e′ exceeds that of acting on e by at most B δ(e, e′), for every prior (simulate e′ from e through the minimising G and act as if the result were e′). The bound also holds with the sharper constant B = the largest entry of the regret_table, which is never more than the range (proved in the Lean development): see largest_regret and deficiency_value_bound.

Computed by the linear programme of deficiency_model, solved by solve_program with the keywords optimizer and rounding_tol: by default the built-in exact simplex. The result is a Rational{BigInt} for rational likelihoods and a float for floating-point ones. With a floating-point optimiser on rational likelihoods the rounded solution must be certified optimal exactly, and ExactVerificationError is thrown when it is not: the value returned for a rational pair is always the exact deficiency.

julia> e = Experiment([4//5 1//5; 1//5 4//5]);

julia> noisy = garble(e, [3//4 1//4; 1//4 3//4]);

julia> deficiency(e, noisy), deficiency(noisy, e)
(0//1, 3//20)

DecisionAnalysis.act_now_value — Function
act_now_value(problem::DecisionProblem)

The value of deciding now, with no further information: the largest expected utility, V0 = max_a Σ_θ p(θ) Q[a, θ], over the feasible actions. Needs a single prior (FiniteBelief or PointBelief).

source
DecisionAnalysis.value_with_information — Function
value_with_information(problem::DecisionProblem, experiment::Experiment)

The value of observing the signal of experiment and then choosing the best action for it:

value(e) = Σ_z max_a Σ_θ p(θ) L[z, θ] Q[a, θ].

This is the joint form: the posterior is never formed, nothing is divided by P(z), and a signal of probability zero contributes exactly zero. The cost of the experiment is not subtracted (see enbs). Needs a single prior.

source
DecisionAnalysis.evpi — Function
evpi(problem::DecisionProblem)

The expected value of perfect information about the state:

EVPI = Σ_θ p(θ) max_a Q[a, θ] − V0.

It is nonnegative, equals the smallest expected_regret, and bounds the evsi of every experiment on the same states. Needs a single prior; for a CredalSet use robust_evpi.

If the payoff table was built from a stochastic simulator with few replicates per cell, every maximum is taken over noisy cells: the act-now value and the value with perfect information are each biased upwards, and the chosen action is on average worth less than its reported score. EVPI is the difference of the two, so the sign of its bias is not determined in general. With exact payoffs and a sampled belief, EVPI is biased downwards. This is a property of the table, not corrected here; see VOIEstimate for the estimates of both biases.

julia> evpi(DecisionProblem(PayoffTable([0 -100; -30 -30]), [3 // 5, 2 // 5]))
18//1
source
evpi(problem::DecisionProblem, method::AbstractVOIMethod; bootstrap=0, seed=1,
     noise_correlation=0) -> VOIEstimate

The expected value of perfect information estimated from a SampleBelief, with its standard error and biases kept apart (VOIEstimate).

  • SampleAverage: the definition on the sample, the number evpi(problem) gives. Right when the cells are exact conditional expectations. When the table has standard errors, bias.cells estimates how much the cell noise inflates its perfect-information term. That estimate takes the noise of different actions in a cell to have the correlation noise_correlation (SampleAverage only). The default, zero, is right for independent runs and overstates the bias under common random numbers, where the noise is shared between actions; pass the achieved correlation, crn_correlation(outcomes, utility).
  • A regression (SplineRegression, GAMRegression, GaussianProcessRegression when the draws carry many parameters): the all-parameter regression estimate. Each action's payoff is regressed on all the parameters of the draws and the fitted values replace the noisy cells, so the simulation noise is smoothed out instead of being maximised over. This is the estimator to use for a stochastic simulator; it reads "the value of learning every parameter", which is the EVPI when the parameters are all that is uncertain apart from the simulator's own randomness. It needs the draws to carry parameters.

bootstrap = B replaces the linearised standard error by the standard deviation over B resamples of the draws; seed seeds the Xoshiro used for the resamples and the bias simulations. See variance_components for the split between parameter and simulation variance.

DecisionAnalysis.evppi — Function
evppi(problem::DecisionProblem, partition::AbstractVector)

The expected value of partial perfect information: the value of learning which cell of a partition the state lies in, and nothing more. partition has one entry per state of the payoff table, in order; states with equal entries are in the same cell (for example the value of one focal parameter when the state is a tuple of parameters).

EVPPI = Σ_cells max_a Σ_{θ ∈ cell} p(θ) Q[a, θ] − V0.

The one-cell partition gives zero and the partition into single states gives evpi; refining a partition never lowers the value. Needs a single prior.

julia> p = DecisionProblem(PayoffTable([0 -10 -60 -150; -20 -20 -25 -90]),
                           [1 // 2, 3 // 10, 3 // 20, 1 // 20]);

julia> evppi(p, [:mild, :mild, :severe, :severe])
33//4

evppi(problem::DecisionProblem, focal, method; bootstrap=0, seed=1) -> VOIEstimate
evppi(problem::DecisionProblem, focal::Symbol; kw...) -> VOIEstimate

The expected value of partial perfect information about the named parameters of a SampleBelief: the value of learning focal (a parameter name, or a tuple or vector of names, columns of the draws) exactly and nothing else. An estimate of the EVPPI defined for evppi(problem, partition), returned with its standard error and biases (VOIEstimate). Methods:

methodfocalidea
Groupingdiscrete, any numberconditional means by cell
StrongOakleyone numericmeans within blocks of the sorted parameter
Sadatsafavione numericbest one or two cut points
SplineRegressionup to about fouradditive regression spline, built in
GAMRegressionup to about fourpenalised smooths, needs GAM.jl
GaussianProcessRegressionfive or moreGaussian process, built in

Without a method, the method is chosen by the focal parameters, by the rule of the R package voi: a regression with smooths for up to four parameters and a Gaussian process from five on. Here that is Grouping() when any focal parameter is not numeric, SplineRegression() for one to four numeric parameters (the built-in stand-in for the generalised additive model, which needs GAM.jl: pass GAMRegression() to use it) and GaussianProcessRegression() for five or more. The method used is recorded in the method field of the result. The single-parameter methods and Grouping need no regression and are useful cross-checks on it. All of them average over the simulation noise in the cells, provided each block, segment or cell holds many draws.

A regression estimate is only as good as its fit. Fitted values are not conditional means when the regression is misspecified or has too few draws for its coefficients, and the estimate is then not bounded by the EVPI: a value above the plain EVPI of a table with little cell noise is a sign of a poor fit, not of valuable information.

bootstrap and seed are as for evpi.

julia> belief = SampleBelief((; site=[:wet, :wet, :dry, :dry], x=[1, 2, 3, 4]));

julia> p = DecisionProblem(PayoffTable([0 0 0 0; 2 4 -4 -6]), belief);

julia> evppi(p, :site).value
3//2

DecisionAnalysis.hypothesis_partition — Function
hypothesis_partition(states, hypothesis)
hypothesis_partition(problem::DecisionProblem, hypothesis)

The two-cell partition that a perfect test of one hypothesis reveals: the state hypothesis on its own, and every other state together (labelled :other). Passed to evppi it gives the value of confirming or refuting that hypothesis, with the weights of the remaining states kept in proportion when it is refuted. This is the quantity that Runge, Converse and Lyons (2011) and Eze et al. (2023) call "EVPXI" for a hypothesis; it is an EVPPI over a particular partition, not a new definition, and it is not the value of learning one parameter of a state that is a tuple of parameters.

julia> p = DecisionProblem(PayoffTable([4 0 0; 1 2 3]), [1 // 2, 1 // 4, 1 // 4]);

julia> hypothesis_partition(p, :s1)
3-element Vector{Symbol}:
 :s1
 :other
 :other

julia> evppi(p, hypothesis_partition(p, :s1)), evpi(p)
(5//4, 5//4)

DecisionAnalysis.two_stage_value — Function
two_stage_value(problem::DecisionProblem, first_stage::AbstractVector;
                partition=nothing)

The value of a two-stage (adaptive) policy in which a first-stage action is chosen on the prior, the cell of partition that holds the state is then learned, and the second-stage action is chosen knowing it.

The actions of problem are the complete two-stage courses of action, and first_stage has one entry per action of the payoff table, in order, naming its first-stage component; actions with equal entries share a first stage. With G the set of first stages,

value = max_{g ∈ G} Σ_cells max_{a : first_stage[a] = g} Σ_{θ ∈ cell} p(θ) Q[a, θ].

partition is as in evppi; the default is the partition into single states (the state is learned exactly after the first stage). The result is a named tuple: value; first_stages and values, the value of committing to each first stage; chosen, every first stage that attains value, in order of appearance; act_now, the value V0 of the best single course of action that ignores what is learned (the best fixed strategy when every fixed strategy is among the actions); and gain, value − act_now. Infeasible actions are left out.

Always act_now ≤ value ≤ act_now + EVPPI(partition): learning after the first stage cannot beat learning before it. The share gain / evppi(problem, partition) is the part of the value of information that the adaptive policy recovers. This is derived from the definitions at the top of src/voi.jl (it is the largest, over first stages, of the informed value of the problem restricted to that first stage). Needs a single prior.

julia> Q = [-4 -9; -5 -6; -8 -3; -8 -7];   # courses: (a,a), (a,b), (b,b), (b,a)

julia> p = DecisionProblem(PayoffTable([:aa, :ab, :bb, :ba], [:s1, :s2], Q), [1 // 2, 1 // 2]);

julia> r = two_stage_value(p, [:a, :a, :b, :b]);

julia> r.value, r.chosen, r.act_now, r.gain
(-5//1, [:a], -11//2, 1//2)

DecisionAnalysis.evsi — Function
evsi(problem::DecisionProblem, experiment::Experiment)

The expected value of sample information: what observing the signal of experiment before choosing is worth, gross of its cost,

EVSI = value(e) − V0,

with value(e) from value_with_information and V0 from act_now_value. What is learned is the signal of this experiment about the states of this problem.

Under a single prior, 0 ≤ EVSI ≤ EVPI, and a garbling of an experiment (garble) has an EVSI no larger than the original (Blackwell). Both statements are for a single prior; under a credal set neither holds in general, and robust_evsi can be negative.

julia> p = DecisionProblem(PayoffTable([0 -100; -30 -30]), [3 // 5, 2 // 5]);

julia> evsi(p, Experiment([4//5 1//5; 1//5 4//5]))
44//5

evsi(problem::DecisionProblem, study; bootstrap=0, seed=1)

The expected value of sample information estimated from a SampleBelief: what the data of study are worth before they are seen, gross of any cost. An estimate of the EVSI defined for evsi(problem, experiment), with its standard error and biases kept apart (VOIEstimate). study says what would be observed and fixes the method:

  • SummaryStatistics: regression of the payoffs on summary statistics of one simulated data set per draw (Strong et al. 2015). Use it when the data reduce to a few numbers.
  • ImportanceSampling: reweighting of the draws by the likelihood of simulated data sets (Menzies 2016). Use it when a log-likelihood is available and no low-dimensional summary is; watch the effective sample sizes in details.
  • GaussianApproximation: shrinkage of the fitted conditional means (Jalal and Alarid-Escudero 2018). Use it for a curve over the sample size; with a vector of sizes the result is a vector of estimates.

The choice follows Kunst et al. (2020, Value in Health 23:734). The estimates are bounded by the EVPPI of what the study informs and by the EVPI only up to Monte Carlo error, since each comes from a different estimator. bootstrap (not available for importance sampling, whose standard error already covers both the data sets and the draws: see ImportanceSampling) and seed are as for evpi.

DecisionAnalysis.enbs — Function
enbs(problem::DecisionProblem, experiment::Experiment; population=1)

The expected net benefit of sampling: population · EVSI − cost, where cost is the cost of the experiment and population scales the per-decision value to the number of decisions the information serves.

This is meaningful only for additive payoffs: the payoff must be in the same units as the cost, and paying the cost must shift every payoff by the same amount whatever the action and state. When utility is not additive in the cost (a risk-averse utility of wealth, for example) the cost belongs in the outcome, as part of each payoff of a larger problem that has "run the experiment" among its actions, and this function does not apply.

source
enbs(estimate::VOIEstimate; cost, population=1) -> NamedTuple

The expected net benefit of sampling from an estimated EVSI: population · EVSI − cost, returned as (; value, standard_error) with the standard error of the estimate scaled by population.

Only for additive payoffs, in the payoff's own unit. The study's cost must be stated in the unit of the payoff (individuals removed or killed by the sampling for a count, money where the payoff is a published valuation), and paying it must lower every payoff by the same amount whatever the action and the state. Never invent a cost. When the cost of a study is not additive in the payoff, it belongs in the outcomes of a larger problem that has "run the study" among its actions.

DecisionAnalysis.information_can_change_decision — Function
information_can_change_decision(problem::DecisionProblem, experiment::Experiment;
                                atol=0, rtol) -> Bool

Whether observing the signal of experiment can change what is done: true exactly when no single action is optimal after every signal of positive probability. When it is false, one action is best whatever is observed, the experiment cannot change the decision, and it is worth nothing.

This is equivalent to a positive value of sample information,

information_can_change_decision(problem, e)  ⟺  evsi(problem, e) > 0,

for a single prior (theorem evsi_eq_zero_iff of the Lean development: EVSI is zero exactly when one action maximises Σ_θ p(θ) L[z, θ] Q[a, θ] for every signal z). The check does not compute the EVSI: it intersects, over the signals of positive probability, the sets of actions that are optimal after each. Ties count: an action that is only tied for best after some signal is still optimal after it.

Optimality after a signal is judged with the tie tolerance of decide (max(atol, rtol · max|score|); zero by default for exact problems, where the equivalence is exact, and rtol = sqrt(eps) in floating point, where it holds up to that tolerance). Needs a single prior.

julia> p = DecisionProblem(PayoffTable([0 -100; -30 -30]), [3 // 5, 2 // 5]);

julia> information_can_change_decision(p, Experiment([4//5 1//5; 1//5 4//5]))
true

julia> information_can_change_decision(p, Experiment([1//2 1//2; 1//2 1//2]))
false

DecisionAnalysis.robust_evpi — Function
robust_evpi(problem::DecisionProblem; rule=GammaMaximin(), optimizer=nothing,
            rounding_tol=(1e-8, 1e-10, 1e-12)) -> RobustVOI

The value of perfect information when the belief is a CredalSet. Two objects are returned in one RobustVOI, because a single "robust EVPI" conflates them.

The rule-specific value. rule must maximise an aggregate over priors (GammaMaximin, DecisionRule(UpperExpectation()) or DecisionRule(AlphaMaxmin(α))). Acting now is worth the rule's best score. With perfect information the best payoff max_a Q[a, θ] is obtained in each state, and that state-contingent payoff is aggregated over the priors in the same way. value is the difference.

The envelope. lower and upper are the smallest and largest single-prior evpi over the whole set. EVPI is concave in the prior, so the smallest is attained at a generating point (lower == minimum(members)), while the largest may lie at an interior prior and is found by the linear programme of evpi_envelope_model (upper ≥ maximum(members)); upper_prior is a prior of the set at which it is attained. optimizer and rounding_tol are passed to solve_program; with a floating-point optimiser on an exact problem the optimum must be certified exactly, or ExactVerificationError is thrown.

A FiniteBelief is treated as a one-point credal set; every number then equals evpi.

source
DecisionAnalysis.robust_evsi — Function
robust_evsi(problem::DecisionProblem, experiment::Experiment;
            rule=GammaMaximin()) -> RobustVOI

The value of an experiment when the belief is a CredalSet, under a rule that maximises an aggregate over priors (as for robust_evpi).

The decision-maker updates every prior in the set by Bayes' rule on the signal (priors that give the signal probability zero drop out), applies rule to the posterior set, and takes its first_choice. That fixes a strategy, one action per signal. informed is the rule's value of that strategy evaluated before the signal is seen, by aggregating its expected payoff over the prior set; act_now is the rule's best score without the signal; value is the difference.

value can be negative, and is returned as computed. Updating a set of priors can widen it (dilation), the posterior choices need not form the strategy the rule would have picked in advance, and so the signal can be worth less than nothing to this decision-maker. Blackwell monotonicity is a statement about single priors.

members holds the single-prior evsi at each generating point. lower and upper are nothing; see RobustVOI.

source
DecisionAnalysis.RobustVOI — Type
RobustVOI

The value of information under a CredalSet, as returned by robust_evpi and robust_evsi. Two different objects are kept apart. Fields:

  • quantity: :evpi or :evsi.
  • rule: the rule under which the rule-specific value is computed.
  • act_now: the rule's value of deciding now.
  • informed: the rule's value of the strategy that waits for the information.
  • value: informed − act_now, the rule-specific value. It may be negative and is returned as computed, never clamped.
  • members: the single-prior value (evpi or evsi) at each generating point of the credal set, in order.
  • lower, upper: the envelope of the single-prior EVPI over the whole credal set. For :evsi both are nothing: EVSI is neither convex nor concave in the prior, so neither end of its envelope is found at a generating point, and version 0.1 does not compute it.
  • upper_prior: a prior in the credal set at which the upper EVPI is attained: the probabilities of the states, in the order of the payoff table, of the mixture of the generating points found by the programme of evpi_envelope_model, so that evpi under it equals upper. It is the belief in the set under which learning the state is worth most, and it is often an interior prior, not a generating point. It need not be unique. nothing for :evsi.

Outcomes, estimation and design

DecisionAnalysis.voi_profile — Function
voi_profile(problem::DecisionProblem, experiment::Experiment; atol=0, rtol) -> NamedTuple

The value of an experiment outcome by outcome (Akinlotan et al. 2024): the expected value of sample information hides how the realised value varies over what the study might show. For each signal z of positive probability the profile gives

  • probability: P(z) = Σ_θ p(θ) L[z, θ];
  • best: the actions that are optimal after z (ties as in decide);
  • posterior_value: the expected utility of the best action after z;
  • value: the value of the information in this outcome, the posterior expected utility of the best action minus that of the act-now action a* (the first Bayes action under the prior). It is never negative, and zero exactly when a* is still optimal after z;
  • changes_decision: whether a* is no longer optimal after z.

The result is (; act_now_action, outcomes, evsi, variance, standard_deviation, probability_zero): evsi = Σ_z P(z) value_z is evsi(problem, experiment) exactly; variance and standard_deviation are those of the per-outcome value over the signals; probability_zero is the probability that the study changes nothing. A study with a large EVSI that comes from a rare outcome has a large standard deviation and a probability_zero near one, which matters to a risk-averse manager. A signal of probability zero is listed with value zero and no posterior. Exact in, exact out, except the standard deviation. Needs a single prior.

julia> p = DecisionProblem(PayoffTable([0 -100; -30 -30]), [3 // 5, 2 // 5]);

julia> profile = voi_profile(p, Experiment([4//5 1//5; 1//5 4//5]));

julia> [(o.signal, o.probability, o.value) for o in profile.outcomes]
2-element Vector{Tuple{Symbol, Rational{Int64}, Rational{Int64}}}:
 (:z1, 14//25, 110//7)
 (:z2, 11//25, 0)

julia> profile.evsi, profile.probability_zero
(44//5, 11//25)

DecisionAnalysis.expected_variance_reduction — Function
expected_variance_reduction(problem, experiment::Experiment, quantity)
expected_variance_reduction(problem, partition::AbstractVector, quantity)
expected_variance_reduction(problem, focal; quantity, method=nothing)

The value of information for estimation: by how much, on average, a study reduces the variance of a quantity of interest (Jackson et al. 2019). quantity has one number per state (the abundance in that state, a parameter, the payoff of one action). With g the quantity,

reduction = Var(g) − E_z Var(g | z) = Var(E[g | z]),

which is never negative. The result is (; prior_variance, expected_posterior_variance, reduction, share) with share = reduction / prior_variance. It measures learning, not deciding: a study can remove most of the variance of a quantity and still have an evsi of zero, when no outcome would change the action, so read the two side by side.

  • With an Experiment: the reduction from observing its signal. Exact.
  • With a partition of the states (as for evppi): the reduction from learning the cell. Exact.
  • With a SampleBelief and focal (a parameter name or a tuple of names): the reduction from learning those parameters, estimated as the weighted variance of the fitted conditional mean of the quantity given them, with method as for evppi (default: chosen by the focal parameters). quantity is a vector with one number per draw, or the name of a parameter of the draws.

Units are those of the quantity squared (individuals squared for a count). Needs a single prior.

julia> p = DecisionProblem(PayoffTable([0 -100; -30 -30]), [3 // 5, 2 // 5]);

julia> r = expected_variance_reduction(p, Experiment([4//5 1//5; 1//5 4//5]), [10, 60]);

julia> r.prior_variance, r.reduction, r.share
(600//1, 16200//77, 27//77)

DecisionAnalysis.optimal_design — Function
optimal_design(problem::DecisionProblem, designs; costs=nothing, population=1,
               seed=1) -> NamedTuple

Compare a finite list of candidate studies and name the best. designs is a named collection (a named tuple, a dictionary or name => design pairs) of

  • Experiments, valued exactly by evsi on a finite problem, or
  • studies of a sample problem (SummaryStatistics, ImportanceSampling, GaussianApproximation), valued by the sample-based evsi, each with its standard error;

or a single GaussianApproximation with a vector of sample sizes, which is compared across its sizes (designs named n = 10, ...).

Each design is scored by its expected net benefit of sampling, population · EVSI − cost. costs gives the cost of each design in individuals (animals removed or killed by the sampling, say): nothing uses the cost of each experiment and zero for the studies; otherwise a vector in the order of the designs, a named collection, or a function of the sample size (of the name, for designs without one). There are no monetary costs in this package, and a net benefit is meaningful only for additive payoffs, as for enbs. When every cost is zero the comparison is by EVSI alone, and the most informative design wins.

The result is (; designs, best, tied, criterion, population): designs holds one (; name, evsi, standard_error, cost, net, net_standard_error) per design (standard errors nothing for exact values); best is the name of the design with the largest net benefit, the first in the order given when several tie (tied lists them all); criterion is :net_benefit or :evsi.

With estimated EVSIs the best design is picked from noisy numbers, so its reported net benefit overstates on average what it is worth (the optimiser's curse, as for the act-now value): read the standard errors, and prefer the smaller study when two are within them.

julia> p = DecisionProblem(PayoffTable([0 -100; -30 -30]), [3 // 5, 2 // 5]);

julia> coarse = Experiment([4//5 1//5; 1//5 4//5]; cost=2);

julia> fine = Experiment([19//20 1//20; 1//20 19//20]; cost=8);

julia> d = optimal_design(p, (; coarse, fine)); (d.best, [x.net for x in d.designs])
(:fine, Rational{Int64}[34//5, 77//10])

Influence diagrams

DecisionAnalysis.normal_form — Function
normal_form(model; states=nothing, baseline=nothing, atol=1e-9) -> NamedTuple

The normal form of a single-decision influence diagram: the payoff table and belief that the diagram defines, as a DecisionProblem, and the decision's information as an Experiment. model is an InfluenceDiagramModel of InfluenceDiagrams.jl (github.com/ecorecipes/InfluenceDiagrams.jl); the method lives in a weak-dependency extension, so load that package first (MissingExtensionError otherwise). InfluenceDiagrams.jl is not a dependency of this package.

  • The actions are the states of the decision's action variable.
  • The state θ is the joint value of the chance variables named in states; by default, every chance variable that could be observed before the decision (those not downstream of it). The belief is their joint distribution, p(θ).
  • The payoff is the conditional expected total utility, Q[a, θ] = E[U | do(a), θ], summing the additive utility nodes of the diagram.
  • The experiment describes what the decision already observes: its information variables that are not part of the state, with likelihood L[z, θ] = P(z | θ); nothing when there are none.

The result is (; problem, experiment, decision, action, states, information, observed). With it, the structural quantities of the diagram are values of information on a payoff table:

  • decide(problem, MaxExpectedUtility()) is the best action with no information;
  • evsi(problem, experiment) is the value of what the decision observes (the diagram's expected_value_of_information for those variables, from none);
  • evpi(problem) is the value of observing the whole state (its expected_value_of_perfect_information from no information), and evpi(problem) − evsi(problem, experiment) what is left to learn.

states must carry everything the information tells about the utility (E[U | a, θ, z] = E[U | a, θ]), otherwise ArgumentError is thrown: add the variables the utility depends on. The diagram is evaluated by enumerating its joint distribution once per action, so this is for small diagrams, and the numbers are floating point, as in InfluenceDiagrams.jl. Utilities are whatever the diagram's utility nodes hold; this package takes the payoff's unit as given.

Fidelity

DecisionAnalysis.total_variation — Function
total_variation(p, q)

The total-variation distance between two probability vectors, or two FiniteBeliefs over the same states:

TV(p, q) = (1/2) Σ_θ |p(θ) − q(θ)| = max_A |p(A) − q(A)|.

The convention is half the ℓ¹ distance, so the result lies in [0, 1]. This is the ε of decision_loss_bound and the distance inside deficiency.

julia> total_variation([1 // 2, 1 // 2], [1 // 4, 3 // 4])
1//4

DecisionAnalysis.decision_loss_bound — Function
decision_loss_bound(B, ε)

The bound 2 B ε on the expected utility lost by deciding under an approximate belief. Conventions, which fix the constant:

  • ε is a total-variation distance, half the ℓ¹ distance (total_variation), between the belief q used to decide and the true belief p.
  • B = sup u − inf u is the range of the utility: the largest payoff in the table minus the smallest (not the largest absolute payoff).

Then for every action |E_p u(a) − E_q u(a)| ≤ B ε, and so the action that is best under q falls short of the best under p, in expectation under p, by at most 2 B ε. With ε an ℓ¹ distance the bound would read B ε; with B a bound on |u| it would read 4 B ε.

The bound also holds with the sharper constant B = max_a (max_θ Q[a, θ] − min_θ Q[a, θ]), the largest range of one action's payoffs across states, which is never more than the range of the table (proved in the Lean development): largest_action_range computes it, and decision_loss_bound(x, ε) on a payoff table or a problem uses it.

julia> decision_loss_bound(150, 1 // 100)
3//1

DecisionAnalysis.largest_action_range — Function

DecisionAnalysis.deficiency_value_bound — Function
deficiency_value_bound(x, δ)

The bound largest_regret(x) · δ on how much more an experiment e′ can be worth than an experiment e in the decision problem x (a PayoffTable or a DecisionProblem), when δ = deficiency(e, e′) is Le Cam's deficiency of e with respect to e′ (deficiency):

value(e′) − value(e) ≤ largest_regret(x) · δ(e, e′)     for every prior.

It uses the sharper constant largest_regret in place of the range of the table (proved in the Lean development). With δ = 0, e′ is a garbling of e and the bound is Blackwell's theorem.

julia> e = Experiment([4//5 1//5; 1//5 4//5]);

julia> noisy = garble(e, [3//4 1//4; 1//4 3//4]);

julia> deficiency_value_bound(PayoffTable([0 -100; -30 -30]), deficiency(noisy, e))
21//2
