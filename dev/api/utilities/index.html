Risk attitude and multi-attribute utilities

A non-linear utility is applied to every run before anything is averaged, and its expected utility is no longer a count of individuals; the certainty equivalent returns to individuals.

Utilities of one outcome

DecisionAnalysis.LinearUtility — Type
LinearUtility(name; worst=nothing, best=nothing)

The risk-neutral utility of the outcome called name: u(x) = x. With worst and best it is scaled to [0, 1],

u(x) = (x − worst) / (best − worst),

so that u(worst) = 0 and u(best) = 1; best < worst describes an outcome that counts against (infected individuals). The scaled form is what AdditiveUtility and MultiplicativeUtility combine.

Linear utility is the reference case of risk attitude: the certainty_equivalent of a lottery is its mean and the risk_premium is zero. Unscaled, expected utility is an expected number of individuals; scaled, it is a fraction of the way from worst to best. Exact in, exact out. Unlike IndividualsUtility it accepts any real outcome.

julia> u = LinearUtility(:frogs; worst=0, best=50); u((; frogs=20))
2//5

julia> certainty_equivalent(u, [10, 30])
20//1

DecisionAnalysis.ExponentialUtility — Type
ExponentialUtility(name; risk_aversion, worst=nothing, best=nothing)

The utility with constant absolute risk aversion r = risk_aversion (per individual) on the outcome called name:

u(x) = (1 − exp(−r x)) / r,        and u(x) = x at r = 0.

r > 0 is risk-averse (a sure number of individuals is preferred to a lottery with the same mean), r < 0 risk-seeking, and 1 / r is the risk tolerance in individuals. The attitude does not depend on the level of the outcome: adding the same number to every result of a lottery adds it to the certainty equivalent.

With worst and best the utility is scaled to [0, 1] and measured along the signed improvement d = σ (x − worst) from the worst level towards the best (with σ = +1 when best > worst and σ = −1 when best < worst), u(x) = v(d) / v(|best − worst|) with v the function above, so best < worst describes an outcome that counts against, and r > 0 is then averse to risk in the improvement.

Expected utility under this utility is not a count of individuals. Use certainty_equivalent to return to individuals, and risk_premium for what the risk costs.

julia> u = ExponentialUtility(:frogs; risk_aversion=0.05);

julia> round(certainty_equivalent(u, [0, 40]); digits=3)   # the mean is 20
11.324
source
DecisionAnalysis.PowerUtility — Type
PowerUtility(name; risk_aversion, worst=nothing, best=nothing)

The utility with constant relative risk aversion ρ = risk_aversion on the outcome called name, a positive number of individuals:

u(x) = x^(1 − ρ) / (1 − ρ),        and u(x) = log(x) at ρ = 1.

ρ = 0 is risk-neutral, ρ > 0 risk-averse and ρ < 0 risk-seeking. The attitude is to proportional changes: multiplying every result of a lottery by the same factor multiplies the certainty equivalent by it. The outcome must be nonnegative, and positive when ρ ≥ 1 (a count of zero then has utility −∞), otherwise InvalidOutcomeError is thrown.

With worst and best (0 ≤ worst < best, and worst > 0 when ρ ≥ 1) the utility is scaled to [0, 1]: u(x) = (v(x) − v(worst)) / (v(best) − v(worst)) with v the function above. An outcome that counts against has no power utility here; use LinearUtility or ExponentialUtility for it.

Expected utility under this utility is not a count of individuals; see certainty_equivalent.

julia> u = PowerUtility(:frogs; risk_aversion=0.5);

julia> round(certainty_equivalent(u, [0, 40]); digits=6)     # the mean is 20
10.0

DecisionAnalysis.inverse_utility — Function
inverse_utility(utility, value)

The outcome whose utility is value: the inverse of a single-attribute utility (LinearUtility, ExponentialUtility, PowerUtility, IndividualsUtility). Applied to an expected utility it gives the certainty_equivalent, in individuals. Throws ArgumentError when no outcome has that utility.

julia> u = PowerUtility(:frogs; risk_aversion=0.5); inverse_utility(u, u(16))
16.0

DecisionAnalysis.certainty_equivalent — Function
certainty_equivalent(utility, lottery::AbstractVector; weights=nothing)
certainty_equivalent(outcomes::OutcomeTable, utility) -> Vector{NamedTuple}

The certainty equivalent of a lottery over one outcome: the sure number of individuals that is exactly as good as the lottery,

CE = u⁻¹(E u(X)).

lottery holds the possible outcomes and weights their probabilities (equal when nothing; normalised). utility is a single-attribute utility (LinearUtility, ExponentialUtility, PowerUtility, IndividualsUtility). An expected utility under a non-linear utility is not a number of individuals; the certainty equivalent returns it to individuals, and is below the mean for a risk-averse utility (risk_premium). To convert an expected utility that is already computed, use inverse_utility.

With an OutcomeTable the lottery of each action is its runs: a draw with its weight, then a usable replicate of that cell with equal chances, which is the lottery whose expected utility is the action's expected payoff under payoff_table. The utility is applied to every run before averaging. One (; action, expected_utility, certainty_equivalent, expected_outcome, risk_premium) per action is returned.

A multi-attribute utility has no certainty equivalent (there is no single outcome to return to) and throws ArgumentError.

julia> u = ExponentialUtility(:frogs; risk_aversion=0.05);

julia> round(certainty_equivalent(u, [0, 40]; weights=[1, 3]); digits=3)   # the mean is 30
20.911
source
DecisionAnalysis.risk_premium — Function
risk_premium(utility, lottery::AbstractVector; weights=nothing)

The risk premium of a lottery over one outcome: how many individuals of expected outcome the decision-maker would give up to be rid of the risk,

risk premium = E X − CE,

with CE the certainty_equivalent. It is zero for a linear utility, positive for a risk-averse one and negative for a risk-seeking one. For an outcome that counts against (best < worst) the sign is turned, CE − E X, so that a positive premium still means risk aversion. It is in individuals.

julia> round(risk_premium(PowerUtility(:frogs; risk_aversion=0.5), [0, 40]); digits=6)
10.0

Several attributes

DecisionAnalysis.AdditiveUtility — Type
AdditiveUtility(utility => weight, ...)
AdditiveUtility(utilities; weights)

The additive multi-attribute utility over named outcomes of one run:

U(x) = Σ_i k_i u_i(x_i),

with u_i the utility of attribute i (a LinearUtility, ExponentialUtility, PowerUtility or any other utility of one run; a bare outcome name stands for LinearUtility(name)) and k_i its weight. The additive form assumes that preferences over lotteries on one attribute do not depend on the levels of the others, and that only the marginal distributions of the attributes matter (additive independence; Keeney and Raiffa 1976).

In the standard use every u_i is scaled to [0, 1] (worst and best given) and the weights are nonnegative and sum to one: U then lies in [0, 1], and k_i is the utility of moving attribute i from its worst to its best level with the others at their worst. The weights are value judgements; show how the choice moves with them (weight_sweep, policy_regions). Unscaled utilities and any real weights are also accepted, which gives the count utilities as special cases: AdditiveUtility(:uninfected => 1, :infected => -w) is InfectionUtility(; weight=w).

Used with payoff_table it is applied to each run before averaging. With scaled attributes expected utility is not a count of individuals, and a multi-attribute utility has no certainty_equivalent. Exact in, exact out when the attribute utilities are linear.

julia> u = AdditiveUtility(LinearUtility(:uninfected; worst=0, best=50) => 3 // 4,
                           LinearUtility(:infected; worst=50, best=0) => 1 // 4);

julia> u((; uninfected=40, infected=10))
4//5

julia> AdditiveUtility(:uninfected => 1, :infected => -1 // 2)((; uninfected=40, infected=6))
37//1
source
DecisionAnalysis.MultiplicativeUtility — Type
MultiplicativeUtility(utility => weight, ...)
MultiplicativeUtility(utilities; weights)

The multiplicative multi-attribute utility of Keeney and Raiffa (1976) over named outcomes of one run:

1 + K U(x) = Π_i (1 + K k_i u_i(x_i)),

with every attribute utility u_i scaled to [0, 1] (give worst and best), and weights 0 < k_i < 1. k_i is the utility of attribute i at its best with all the others at their worst. The interaction constant K > −1 is the nonzero root of 1 + K = Π_i (1 + K k_i), found by bisection and stored in the field interaction; U lies in [0, 1].

  • Σ k_i = 1: K = 0 and the form reduces to the AdditiveUtility.
  • Σ k_i > 1: −1 < K < 0, the attributes are substitutes (doing well on one makes up for another);
  • Σ k_i < 1: K > 0, the attributes are complements (doing well on all of them together is worth more than the sum).

The form assumes mutual utility independence of the attributes, which is weaker than the additive independence of the additive form. An attribute utility outside [0, 1] in a run (an outcome beyond worst or best) throws InvalidOutcomeError. Used with payoff_table it is applied to each run before averaging; expected utility is not a count of individuals, and there is no certainty_equivalent.

julia> u = MultiplicativeUtility(LinearUtility(:uninfected; worst=0, best=50) => 0.6,
                                 LinearUtility(:infected; worst=50, best=0) => 0.6);

julia> round(u.interaction; digits=4)
-0.5556

julia> round(u((; uninfected=50, infected=50)); digits=4)   # one attribute at its best
0.6

julia> round(u((; uninfected=50, infected=0)); digits=4)    # both
1.0

Certainty-equivalent value of information

DecisionAnalysis.ce_evpi — Function
ce_evpi(problem::DecisionProblem, utility::AbstractUtility) -> NamedTuple
ce_evpi(outcomes::OutcomeTable, utility::AbstractUtility) -> NamedTuple

The certainty-equivalent expected value of perfect information in outcome units (individuals): the maximum state-independent deduction v* ≥ 0 along the improvement direction that a decision-maker with single-attribute risk utility utility (IndividualsUtility, LinearUtility, ExponentialUtility, PowerUtility) would trade for perfect information about the state (Howard's buying price, solving V_info(v*) = V_0).

On a DecisionProblem, problem.payoff.Q must hold raw outcome levels (before utility is applied), with a single prior. On an OutcomeTable, utility is applied to every usable replicate before averaging, preserving Jensen's inequality.

  • For linear utilities (IndividualsUtility, LinearUtility), value equals the outcome-scale evpi (exact for rational inputs).
  • For ExponentialUtility (CARA), translation invariance yields the exact closed form σ · (informed_ce − act_now_ce), computed in log-space without saturation.
  • For PowerUtility (CRRA), wealth effects separate the buying price value from ce_gain = informed_ce − act_now_ce; value is found by monotone bisection. If ρ < 1 and even deducting the full domain bound still leaves expected utility above V_0, domain_limited is true and value is nothing while ce_gain is still reported.

Returns (; value, ce_gain, act_now_ce, informed_ce, act_now_utility, informed_utility, domain_limited).
