Linear programmes, reports, certificates and exceptions

Linear programmes

Every linear programme of the package is stated once, as a JuMP model, by an exported builder. solve_program solves one by the built-in exact simplex or by any JuMP optimiser; the functions above (decide with EAdmissible, is_garbling_of, deficiency, robust_evpi) build, solve and verify.

DecisionAnalysis.eadmissibility_model — Function
eadmissibility_model(problem::DecisionProblem, action) -> DecisionProgram

The linear programme that decides whether action (a label among the feasible actions) is E-admissible in problem, whose belief is a CredalSet or a single prior. With E[b, k] = Σ_θ p_k(θ) Q[b, θ] the expected utility of the feasible action b at the generating point p_k, n feasible actions and K generating points, it is

maximise    t
subject to  Σ_k λ_k = 1,                                 (simplex)
            Σ_k λ_k (E[a, k] − E[b, k]) − t ≥ 0   for every action b,   (optimal[b])
            λ_k ≥ 0,  t free.

The row b = a reads t ≤ 0, so the optimum is at most zero, and a is E-admissible exactly when it is zero; Σ_k λ_k p_k is then a prior in the set under which a maximises expected utility.

Shape: K + 1 variables (variables.λ, a vector of K, and variables.t) and n + 1 constraints (constraints.simplex and constraints.optimal, a vector of n), plus the K lower bounds on λ.

This is the programme that decide(problem, EAdmissible()) solves for each action.

DecisionAnalysis.garbling_model — Function
garbling_model(e′::Experiment, e::Experiment) -> DecisionProgram

The feasibility programme that decides whether e′ is a garbling of e. With L the likelihood of e (nz signals by S states) and L′ that of e′ (nz′ signals), find a matrix G (nz′ by nz, G[z′, z] = P(z′ | z)) with

Σ_z′ G[z′, z] = 1                      for every signal z of e,       (columns[z])
Σ_z G[z′, z] L[z, θ] = L′[z′, θ]       for every z′ and state θ,      (product[z′, θ])
G[z′, z] ≥ 0.

There is no objective. The programme is feasible exactly when e′ is a garbling of e, and any feasible G is a witness (G * L == L′).

Shape: nz′ · nz variables (variables.G, a matrix) and nz + nz′ · S equality constraints (constraints.columns, constraints.product), plus the lower bounds.

This is the programme behind is_garbling_of for exact likelihoods and a zero tolerance; a floating-point pair is tested through deficiency_model.

DecisionAnalysis.deficiency_model — Function
deficiency_model(e::Experiment, e′::Experiment) -> DecisionProgram

The linear programme for Le Cam's deficiency of e with respect to e′. With L the likelihood of e (nz signals by S states) and L′ that of e′ (nz′ signals), over a garbling matrix G (nz′ by nz), absolute deviations u (nz′ by S) and a bound d:

minimise    d
subject to  Σ_z′ G[z′, z] = 1                              for every z,        (columns[z])
            Σ_z G[z′, z] L[z, θ] − u[z′, θ] ≤ L′[z′, θ]    for every z′, θ,    (above[z′, θ])
            Σ_z G[z′, z] L[z, θ] + u[z′, θ] ≥ L′[z′, θ]    for every z′, θ,    (below[z′, θ])
            Σ_z′ u[z′, θ] − d ≤ 0                          for every θ,        (total[θ])
            G ≥ 0,  u ≥ 0,  d ≥ 0.

At the optimum d = min_G max_θ ‖G L[·, θ] − L′[·, θ]‖₁, twice the deficiency (total variation is half the ℓ¹ distance): deficiency(e, e′) = d / 2. The programme is always feasible and bounded.

Shape: nz′ · nz + nz′ · S + 1 variables (variables.G, variables.u, variables.d) and nz + 2 · nz′ · S + S constraints (constraints.columns, constraints.above, constraints.below, constraints.total), plus the lower bounds.

This is the programme that deficiency solves.

DecisionAnalysis.evpi_envelope_model — Function
evpi_envelope_model(problem::DecisionProblem) -> DecisionProgram

The linear programme for the largest single-prior evpi over the credal set of problem (the upper end of the envelope in robust_evpi). With E[a, k] the expected utility of the feasible action a at the generating point p_k, m_k = Σ_θ p_k(θ) max_a Q[a, θ] the value with perfect information at p_k, n feasible actions and K generating points:

maximise    Σ_k λ_k m_k − w
subject to  Σ_k λ_k = 1,                                (simplex)
            Σ_k λ_k E[a, k] − w ≤ 0   for every action a,   (act_now[a])
            λ_k ≥ 0,  w free.

At the optimum w is the act-now value under the prior Σ_k λ_k p_k, so the objective is the EVPI at that prior. EVPI is concave in the prior, which is why its maximum over the hull is a linear programme while its minimum is at a generating point. The programme is always feasible and bounded.

Shape: K + 1 variables (variables.λ, variables.w) and n + 1 constraints (constraints.simplex, constraints.act_now), plus the K lower bounds on λ.

DecisionAnalysis.mixed_dominance_model — Function
mixed_dominance_model(problem::DecisionProblem, action) -> DecisionProgram

The linear programme that looks for a mixed action that strictly beats action at every generating point of the credal set of problem: the dual of eadmissibility_model, stated as a programme of its own so that a "not E-admissible" answer has a witness that can be checked. With E[b, k] the expected utility of the feasible action b at the generating point p_k, n feasible actions and K generating points, it is

maximise    s
subject to  Σ_b μ_b = 1,                                         (simplex)
            Σ_b μ_b (E[b, k] − E[a, k]) − s ≥ 0   for every k,    (dominates[k])
            μ_b ≥ 0,  s free.

Taking μ to be all on a gives s = 0, so the optimum is at least zero, and it is positive exactly when a is not E-admissible (linear-programming duality; Lean theorem not_isEAdmissible_iff_isMixedDominated). The mixture μ is then better than a by at least s under every prior of the set.

Shape: n + 1 variables (variables.μ, a vector of n, and variables.s) and K + 1 constraints (constraints.simplex and constraints.dominates, a vector of K), plus the n lower bounds on μ.

This is the programme behind export_not_eadmissible_witness.

DecisionAnalysis.separating_payoff_model — Function
separating_payoff_model(e′::Experiment, e::Experiment) -> DecisionProgram

The linear programme that looks for a decision problem in which e′ is worth strictly more than e, which exists exactly when e′ is not a garbling of e (Blackwell's theorem; Lean theorem not_isGarblingOf_iff_exists_separating). The actions of the problem are the signals of e′, its prior is uniform, and its payoff table is the unknown V[z′, θ]. With L the likelihood of e (nz signals by S states) and L′ that of e′ (nz′ signals),

maximise    Σ_{z′, θ} L′[z′, θ] V[z′, θ] − Σ_z u_z
subject to  u_z ≥ Σ_θ L[z, θ] V[z′, θ]     for every z and z′,   (best[z, z′])
            −1 ≤ V[z′, θ] ≤ 1,  u_z free.

At the optimum u_z is the best that can be done after signal z of e, so Σ_z u_z is S times the value of e, and the first sum is S times the value of taking action z′ after signal z′ of e′, a lower bound on the value of e′. V = 0 gives zero, so the optimum is at least zero, and it is positive exactly when e′ is not a garbling of e. The bounds on V only fix the scale.

Shape: nz′ · S + nz variables (variables.V, a matrix, and variables.u, a vector) and nz · nz′ constraints (constraints.best), plus the bounds on V.

This is the programme behind export_not_garbling_witness.

DecisionAnalysis.DecisionProgram — Type
DecisionProgram{T}

A linear programme of this package as a JuMP model, returned by the builders eadmissibility_model, garbling_model, deficiency_model, evpi_envelope_model, mixed_dominance_model and separating_payoff_model. Fields:

  • name: :e_admissibility, :garbling, :deficiency, :evpi_envelope, :mixed_dominance or :separating_payoff.
  • model: the JuMP.GenericModel{T}. T is Rational{BigInt} when the problem is exact (Rational or integer entries) and the floating-point type of the problem otherwise. No optimiser is attached.
  • variables: a named tuple of the model's variable references, with the names used in the builder's docstring.
  • constraints: a named tuple of its constraint references.

The model is an ordinary JuMP model: it can be printed, extended, given an optimiser and solved directly, or passed to solve_program, which also reads the solution back in the shape of variables.

DecisionAnalysis.solve_program — Function
solve_program(program::DecisionProgram; optimizer=nothing, rounding_tol=(1e-8, 1e-10, 1e-12))
    -> ProgramSolution

Solve a programme built by eadmissibility_model, garbling_model, deficiency_model or evpi_envelope_model. There are three routes to the same model.

  • optimizer = nothing (the default): the built-in exact simplex. The matrix form of the model is read with JuMP.lp_matrix_data and solved in Rational{BigInt} by a dense two-phase simplex method with Bland's rule. No solver needs to be installed. It is meant for small problems (tens of variables and constraints). A floating-point model is solved as the exact rationals its numbers are and the result converted back.
  • An exact optimiser, one that accepts the model's number type, for example CDDLib.Optimizer{Rational{BigInt}} for a rational model (or any floating-point optimiser for a floating-point model). It is attached to program.model and run. For a rational model the point it returns is checked to satisfy every constraint exactly (ExactVerificationError otherwise).
  • A floating-point optimiser on a rational model, for example HiGHS.Optimizer. A Float64 copy of the matrix form is solved; the primal and dual solutions are rounded with rationalize(BigInt, x; tol); and the rounded pair is checked against the rational data: the primal point satisfies every constraint exactly, the dual point is dual feasible, and the two objectives are equal (for a feasibility programme, the first of these alone). When they hold the rounded point is optimal by weak duality and the solution is marked exact. rounding_tol is the tolerance tol, or several to be tried in order until one passes (a coarse tolerance recovers simple fractions from a loose solution, a fine one recovers large denominators from a tight solution; trying several is sound because each rounding is verified). When none passes, the point rounded at the first tolerance is returned with exact = false, and it is for the caller to verify what it needs or to refuse: the functions of this package that call solve_program throw ExactVerificationError before they would return an unverified number.

Which of the last two routes applies is decided by asking the optimiser whether it supports linear constraints in the model's number type. An optimiser that supports neither that type nor Float64 throws an ArgumentError.

optimizer is anything JuMP.set_optimizer accepts: an optimiser type or JuMP.optimizer_with_attributes(...).

DecisionAnalysis.ProgramSolution — Type
ProgramSolution{T}

What solve_program returns. Fields:

  • status: :optimal, :infeasible, :unbounded, or the lower-case name of another termination status of an external optimiser.
  • objective: the objective value at values (zero for a feasibility programme), or nothing when the status is not :optimal.
  • values: the solution, a named tuple with the names and shapes of the programme's variables; empty when the status is not :optimal.
  • route: :internal (the built-in exact simplex), :exact_optimizer (an optimiser working in the rational number type of the model) or :float_optimizer (a floating-point optimiser: with rounding on a rational model, as it is on a floating-point one).
  • exact: whether status, objective and values are exact statements about the programme. It is true for a rational programme solved by the internal simplex or by an exact optimiser, and for a rounded floating-point solution whose optimality was certified exactly (see solve_program). It is false for a floating-point programme, for a rounded solution that was not certified (then values and objective are the rounded numbers, unverified), and for an :infeasible or :unbounded verdict of a floating-point optimiser.

Reports and certificates

DecisionAnalysis.DecisionReport — Type
DecisionReport(problem::DecisionProblem; credal=nothing, experiment=nothing,
               experiments=nothing, partitions=nothing, objectives=nothing,
               pareto=nothing, hurwicz=nothing, assumptions=String[],
               optimizer=nothing, parameters=nothing,
               regression=SplineRegression(), seed=1, noise_correlation=0,
               profile=false, quantities=nothing)

Everything the package can say about one problem, side by side, so that a decision that is contested between rules is seen to be contested. Which parts are filled depends on the belief:

  • State-wise rules, always: Maximin, Maximax, Laplace, MinimaxRegret, and Hurwicz when the optimism index hurwicz is given; the max_regret profile.
  • With a single prior (FiniteBelief, SampleBelief or PointBelief): MaxExpectedUtility, the expected_regret profile, evpi, the evsi of every experiment given, and the evppi of every partition given.
  • With a credal set, either as the belief of the problem or passed as credal beside a single prior: GammaMaximin, the robust sets EAdmissible, Maximal and IntervalDominance, and robust_evpi.

Sample-based problems. When the belief is a SampleBelief, every number under the single prior is an estimate, and the report adds a Monte Carlo section in which standard errors are shown beside the values and never folded into them: the expected utility of each action with its standard error (expected_utility_estimates) and, with a baseline, the expected gain with its own (expected_gain_estimates); the EVPI with its standard error and the two selection biases (VOIEstimate); when the payoff table has standard errors, the split of each action's variance between parameters and simulation (variance_components) and the all-parameter regression estimate of EVPI with regression (skipped, with a note, when the draws carry no parameters or are too few for it; regression = nothing turns it off); and the EVPPI of each parameter named in parameters (names of columns of the draws, or tuples of names) by the default method of evppi. A table built from one run per cell is flagged (single_replicate). The worst and best cases are over the sampled draws and say so; Laplace is left out, since an unweighted mean over draws ignores their weights. seed seeds the bias simulations, and noise_correlation is the correlation of the cell noise between actions used for the cell-noise bias (zero by default; pass crn_correlation for a table simulated with common random numbers).

Experiments and partitions. experiments is a named collection of Experiments (a named tuple, a dictionary, or name => experiment pairs); experiment is a single one, reported under the name experiment, and may be given as well. For each the report gives the EVSI, its cost, the net value EVSI − cost (enbs with population = 1, meaningful for additive payoffs only) and whether the experiment can change the decision (information_can_change_decision); an experiment that cannot is worth nothing, and the report says so. partitions is a named collection of partitions of the states (each a vector with one entry per state, as for evppi); for each the report gives the EVPPI. Both need a single prior (BeliefFormError otherwise).

Optional sections. With profile = true the report adds, for every experiment, its value outcome by outcome (voi_profile): the probability of each signal, the action chosen after it and what that outcome is worth, with the standard deviation of the realised value and the probability that the study changes nothing. quantities is a named collection of quantities of interest, each a vector with one number per state; the report then adds the value of information for estimation, the expected reduction of the variance of each quantity by each experiment and each partition (expected_variance_reduction). Both need a finite single prior and experiments or partitions to report on.

Several objectives. objectives is a named collection of payoff tables on the actions and states of the problem, one per objective, all utilities (higher is better). The report then has a multi-objective section: the ParetoFront of the feasible actions under the belief of the problem. pareto is the rule to use; by default the objectives are scored by expectation under a single prior, by lower expectation over a credal set and by worst case over a scenario set.

Baseline. When the problem has a baseline action (no intervention), the report states it in its header, gives every action's gain over it, and says for every rule whether the action chosen is the baseline. Under a single prior the gain is the expected gain; under a credal set it is the range of the expected gain over the set, and under a scenario set the range of the gain over the scenarios (see expected_gain_over_baseline). When there is no baseline, the assumptions say so.

Minimax regret depends on the menu of actions, and the report says so under the first choices: see MinimaxRegret.

optimizer is passed to the linear programmes behind the robust sets and the EVPI envelope (see solve_program); by default they are solved exactly by the built-in simplex.

Fields:

  • problem.
  • results: the scalar rules, a vector of DecisionResult; robust: the set-valued rules.
  • max_regret, expected_regret.
  • expected_gain: the expected gain over the baseline under a single prior; gain_range: the named tuple (lower, upper) for a credal set or a scenario set.
  • evpi; evsi: the EVSI of the first experiment given.
  • experiments: one named tuple (name, evsi, cost, net, can_change_decision) per experiment; partitions: one named tuple (name, evppi) per partition.
  • robust_evpi.
  • pareto: the result of the Pareto front, when objectives were given.
  • assumptions: the stated assumptions under which the numbers hold, to which the strings in the assumptions keyword are appended.
  • profiles: with profile = true, one (; name, profile) per experiment; estimation: with quantities, one (; source, quantity, prior_variance, expected_posterior_variance, reduction, share) per experiment or partition and quantity.
  • monte_carlo: for a sample-based problem, the named tuple (; expected_utility, expected_gain, evpi, evpi_regression, evppi, variance, single_replicate) of the estimates described above (nothing where one does not apply).

A field that does not apply is nothing (or empty).

A report prints as text that fits 80 columns: tables of actions against rules (in blocks of a few rules when there are many), with aligned columns. In a notebook or a Quarto document it renders as Markdown or HTML tables. It is also a Tables.jl row table with one row per feasible action: the action, each scalar rule's score and whether it chose the action, the regret profile, the gain over the baseline when there is one (expected_gain_over_baseline, or gain_over_baseline_lower and gain_over_baseline_upper), membership of each robust set, and of the Pareto front.

DecisionAnalysis.export_decision_certificate — Function
export_decision_certificate(io::IO, problem::DecisionProblem; experiment=nothing)
export_decision_certificate(path::AbstractString, problem; experiment=nothing)

Write a certificate for problem: the data of the problem and the numbers this package claims for it, as JSON with schema "decision-certificate/1" (CERTIFICATE_SCHEMA), for an independent checker (the Lean development) to recompute in exact arithmetic.

The problem must be exact: payoffs, prior and likelihood of Rational or integer type, otherwise InexactCertificateError is thrown. It needs a single prior (FiniteBelief or PointBelief). Only the feasible actions are written, and action indices in the claims refer to that list.

Every number is a string "n/d" in lowest terms, or "n" when the denominator is one; action indices are JSON integers counted from zero. The object holds schema, actions, states, payoff (rows = actions), prior, with an experiment signals and likelihood (rows = signals), and claims: expected_utility, act_now_value, bayes_actions, regret (rows = actions), expected_regret, max_regret, minimax_regret_actions, evpi, and with an experiment value_with_information and evsi. The manual page "Certificates" gives the definition of each claim.

The path form returns the path; the IO form returns nothing.

DecisionAnalysis.export_garbling_witness — Function
export_garbling_witness(io::IO, e′::Experiment, e::Experiment; optimizer=nothing,
                        rounding_tol=(1e-8, 1e-10, 1e-12))
export_garbling_witness(path::AbstractString, e′, e; optimizer=nothing,
                        rounding_tol=(1e-8, 1e-10, 1e-12))

Write the proof that e′ is a garbling of e: the two likelihoods and the matrix G found by is_garbling_of, as JSON with schema "garbling-witness/1" (GARBLING_WITNESS_SCHEMA). The object holds schema, experiment (the likelihood of e, rows = signals), garbled (the likelihood of e′) and garbling (G[z′][z] = P(z′ | z), rows = signals of e′, columns = signals of e), every number a string "n/d" or "n" as in export_decision_certificate.

Both likelihoods must be of Rational or integer type (InexactCertificateError otherwise). By default the programme is solved exactly and no rounding is involved; optimizer and rounding_tol choose another route (see solve_program). The solver is never trusted: whatever found the witness, it is checked here in exact arithmetic before a byte is written: G is nonnegative, every column of G sums to one, and G * L_e equals L_e′ entry for entry. WitnessError is thrown when e′ is not a garbling of e, or if that check fails; ExactVerificationError when a floating-point optimiser reports a garbling that does not round to an exact one.

The path form returns the path; the IO form returns nothing.

DecisionAnalysis.export_eadmissible_witness — Function
export_eadmissible_witness(io::IO, problem::DecisionProblem, action;
                           optimizer=nothing, rounding_tol=(1e-8, 1e-10, 1e-12))
export_eadmissible_witness(path::AbstractString, problem, action; optimizer=nothing,
                           rounding_tol=(1e-8, 1e-10, 1e-12))

Write the proof that action (a label) is E-admissible in problem: a prior in the credal set under which it maximises expected utility, with the convex weights that place that prior in the set, as JSON with schema "e-admissible-witness/1" (EADMISSIBLE_WITNESS_SCHEMA). The object holds schema, payoff (rows = the feasible actions), priors (the generating points of the credal set, one per row), weights (one per generating point), prior (the mixture Σ_k weights[k] · priors[k]) and action (a JSON integer counted from zero among the feasible actions); every other number is a string "n/d" or "n".

The belief is a CredalSet, or a single prior read as a one-point set. The payoffs and priors must be of Rational or integer type (InexactCertificateError otherwise). By default the E-admissibility programme is solved exactly and no rounding is involved; optimizer and rounding_tol choose another route (see solve_program). The solver is never trusted: whatever found the weights, the witness is checked here in exact arithmetic before a byte is written: the weights are nonnegative and sum to one, the prior is their mixture, and no action has a higher expected utility under it. WitnessError is thrown when the action is not E-admissible, or if that check fails; ExactVerificationError when a floating-point optimiser reports it E-admissible with weights that do not round to a witness; an ArgumentError when the action is not a feasible action.

The path form returns the path; the IO form returns nothing.

DecisionAnalysis.export_not_eadmissible_witness — Function
export_not_eadmissible_witness(io::IO, problem::DecisionProblem, action;
                               optimizer=nothing, rounding_tol=(1e-8, 1e-10, 1e-12))
export_not_eadmissible_witness(path::AbstractString, problem, action; kw...)

Write the proof that action (a label) is not E-admissible in problem: a mixed action that is strictly better than it at every generating point of the credal set, and therefore under every prior of the set, as JSON with schema "not-e-admissible-witness/1" (NOT_EADMISSIBLE_WITNESS_SCHEMA). The object holds schema, payoff (rows = the feasible actions), priors (the generating points, one per row), action (a zero-based index into the feasible actions), mixed_action (a probability vector over the feasible actions) and the labels actions and states.

The mixed action is found by the programme of mixed_dominance_model, the dual of the E-admissibility programme, by any route of solve_program. The solver is never trusted: the mixture is checked here in exact arithmetic before a byte is written (nonnegative, summing to one, and strictly better than action at every generating point), so a "no" found by a floating-point optimiser becomes an exact statement once its rounded witness passes. Such a witness exists whenever the action is not E-admissible.

The payoffs and the credal set must be exact (InexactCertificateError otherwise). WitnessError is thrown when no witness passes the check, which is the case when the action is E-admissible. The path form returns the path; the IO form returns nothing.

DecisionAnalysis.export_not_garbling_witness — Function
export_not_garbling_witness(io::IO, e′::Experiment, e::Experiment; optimizer=nothing,
                            rounding_tol=(1e-8, 1e-10, 1e-12))
export_not_garbling_witness(path::AbstractString, e′, e; kw...)

Write the proof that e′ is not a garbling of e: a decision problem in which deciding after e′ is worth strictly more than deciding after e, which a garbling can never be. JSON with schema "not-garbling-witness/1" (NOT_GARBLING_WITNESS_SCHEMA): schema, experiment (the likelihood of e, rows = signals), garbled (the likelihood of e′), payoff (the separating payoff table, one action per signal of e′) and prior (uniform, so that every state is visible).

The payoff table is found by the programme of separating_payoff_model, by any route of solve_program. The solver is never trusted: before a byte is written, both values are recomputed in exact arithmetic in the joint form of value_with_information and the one of e′ is checked to be strictly larger. Any table that passes is a valid witness, whatever rounding it went through, so a "no" found by a floating-point optimiser becomes an exact statement. Such a witness exists whenever e′ is not a garbling of e.

Both likelihoods must be exact (InexactCertificateError otherwise). WitnessError is thrown when no table passes the check, which is the case when e′ is a garbling of e. The path form returns the path; the IO form returns nothing.

Exceptions

DecisionAnalysis.DecisionAnalysisError — Type
DecisionAnalysisError

Abstract supertype of every exception that DecisionAnalysis defines: InvalidBeliefError, InvalidPayoffError, InvalidExperimentError, LabelMismatchError, BeliefFormError, NoFeasibleActionError, InvalidBaselineError, MissingBaselineError, InexactCertificateError, WitnessError, LinearProgramError, ExactVerificationError, InvalidOutcomeError and MissingExtensionError. It marks the package that introduced an error, not a kind of failure. Invalid arguments and keywords raise Base's ArgumentError instead, which is outside this root.

InvalidBeliefError(msg)

Thrown when a belief is not what its type requires: a probability vector with a negative or non-finite entry or a sum different from one, an empty credal set, an empty scenario set, or duplicate state labels.

DecisionAnalysis.InvalidExperimentError — Type
InvalidExperimentError(msg)

Thrown when the likelihood of an Experiment, or a garbling matrix passed to garble, is not column-stochastic (entries nonnegative, every column summing to one) or does not match its labels.

DecisionAnalysis.LabelMismatchError — Type
LabelMismatchError(what, expected, got)

Thrown when two objects that must share labels do not: the states of a belief or an experiment against the states of a payoff table, the actions of two problems compared by ParetoFront, or the labels of two payoff tables that are added or subtracted. what names the pairing.

DecisionAnalysis.BeliefFormError — Type
BeliefFormError(operation, belief, msg)

Thrown when operation is not defined for the form of belief it was given, for example an expectation over a ScenarioSet (which carries no probabilities) or evpi on a CredalSet (use robust_evpi). belief is the name of the belief type and msg says what to use instead.

DecisionAnalysis.InexactCertificateError — Type
InexactCertificateError(what, eltype)

Thrown by export_decision_certificate when part of the problem (what: the payoff, the prior or the likelihood) has an element type that is not an exact rational or integer. A certificate is checked in exact arithmetic, so a floating-point problem cannot be certified.

DecisionAnalysis.WitnessError — Type
WitnessError(msg)

Thrown by export_garbling_witness and export_eadmissible_witness when there is no witness to export (the experiment is not a garbling, the action is not E-admissible) or when the witness found does not pass the exact check that is made before anything is written.

DecisionAnalysis.LinearProgramError — Type
LinearProgramError(problem, status)

Thrown when a linear programme that is feasible and bounded by construction is reported otherwise by the solver that was used (the built-in simplex or the optimizer that was passed). problem names the programme (:e_admissibility, :deficiency, :evpi_envelope) and status is :infeasible, :unbounded, or the lower-case name of another termination status of the optimiser (for example :time_limit). With the built-in solver this error means a bug, not bad input; with an external optimiser it may mean that the optimiser failed.

source
DecisionAnalysis.ExactVerificationError — Type
ExactVerificationError(problem, msg)

Thrown when a floating-point optimizer was used on an exact (Rational or integer) problem and its answer, rounded to rationals, did not pass the exact check that every answer must pass before it is returned: a witness that is not exactly a witness, or an optimal value that the rounded primal and dual solutions do not certify. problem names the programme (:e_admissibility, :garbling, :deficiency, :evpi_envelope) and msg says which check failed. Nothing unverified is returned in its place. The default route (optimizer = nothing) and an exact optimiser do not round and do not throw this error; a different rounding_tol may also help.

DecisionAnalysis.InvalidOutcomeError — Type
InvalidOutcomeError(msg)

Thrown when an OutcomeTable cannot be built or used as asked: a run that appears twice, an outcome that is not a finite number in a run whose status is acceptable, a cell (draw × action) with no usable run when a payoff is asked of it, or an outcome name that the table does not have.

source
DecisionAnalysis.MissingExtensionError — Type
MissingExtensionError(method, package)

Thrown when a method that lives in a weak-dependency extension is used before the package that triggers the extension has been loaded: for example GAMRegression without using GAM. method names the method and package the package to load.
