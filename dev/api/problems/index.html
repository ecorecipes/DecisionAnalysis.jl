Beliefs, payoff tables and problems

DecisionAnalysis — Module
DecisionAnalysis

Standard decision analysis on finite problems, with no category theory required: a payoff table, a belief about its states, rules for choosing, Savage regret, and the value of information, all exact when the inputs are rational.

A PayoffTable holds the conditional expected utility Q[a, θ] of each action in each state (rows = actions, columns = states). A belief is a PointBelief, a FiniteBelief, a CredalSet or a ScenarioSet, and a DecisionProblem pairs the two. decide applies a rule: MaxExpectedUtility, Maximin, Maximax, MinimaxRegret, GammaMaximin, Satisfice, or the set-valued EAdmissible, Maximal, IntervalDominance and ParetoFront. A scalar rule is an aggregator, an optional transform and a selector (DecisionRule), and the same pieces without the selector are a RobustnessMetric.

An Experiment is a likelihood matrix L[z, θ] = P(z | θ) (rows = signals, columns = states); bayes_invert, garble, is_garbling_of and deficiency work on experiments, and evpi, evppi, evsi and enbs value information exactly. DecisionReport puts every applicable rule side by side, and export_decision_certificate, export_garbling_witness and export_eadmissible_witness write a problem, its claimed numbers and the witnesses found by linear programme for the Lean checker.

A payoff table can be assembled from tables of outcome counts (combine_payoffs, individuals_payoff, infection_payoff, and +, -, scalar * on tables with matching labels).

Every linear programme is stated once as a JuMP model by an exported builder (eadmissibility_model, garbling_model, deficiency_model, evpi_envelope_model) and solved by solve_program: by default with the built-in exact simplex, otherwise with the optimizer given, exact or floating point. No solver is trusted: witnesses are verified in exact arithmetic before they are returned.

Sample-based analysis sits on the same definitions. A SampleBelief holds draws of named parameters with weights; an OutcomeTable holds what a model produced by draw × action × replicate, built from any table of runs or by outcomes through the adapter verbs (with_parameters, apply_action, simulate, outcome); a utility counted in individuals (IndividualsUtility, InfectionUtility) turns it into a payoff table with its Monte Carlo standard errors kept apart (payoff_table). evpi, evppi and evsi called with a method (SampleAverage, Grouping, StrongOakley, Sadatsafavi, SplineRegression, SummaryStatistics, ImportanceSampling, GaussianApproximation) return a VOIEstimate: the value, its standard error and its selection biases, never folded together. policy_regions, weight_sweep and rank_reversals show how the choice moves with a weight.

Finite problems are exact; sample-based results are estimates of the same quantities. The package depends on FiniteKernels for kernels and states, on JuMP for stating linear programmes (and on no solver), and never on Catlab, GATlab or ACSets. GAM.jl is an optional regression backend through a weak-dependency extension (GAMRegression). It defines none of compose, otimes, id, mcopy, delete, braid, dom, codom, and exports no regret or regrets.

Beliefs

DecisionAnalysis.AbstractBelief — Type
AbstractBelief

Supertype of the belief forms: PointBelief, FiniteBelief, SampleBelief, CredalSet and ScenarioSet. A belief says what is known about the state; which rules and which value-of-information quantities are defined depends on its form, and an operation that is not defined for a form throws BeliefFormError instead of guessing.

DecisionAnalysis.PointBelief — Type
PointBelief(state)

The state is known: all mass on the one labelled state (a symbol or a string). Every aggregator returns the payoff in that state, and the value of further information is zero.

julia> PointBelief(:high).state

DecisionAnalysis.FiniteBelief — Type
FiniteBelief(states, probabilities; atol)
FiniteBelief(probabilities; atol)
FiniteBelief(k::FiniteKernel)

A probability vector over labelled states. probabilities must be finite, nonnegative and sum to one, exactly for Rational or integer entries and within atol (default 1e-8) for floating point; otherwise InvalidBeliefError is thrown. Without states the labels are :s1, :s2, ..., which are also the default state labels of a PayoffTable.

The third form takes a state of FiniteKernels (a FiniteKernel with an empty domain). A one-axis space keeps its labels; the joint states of a several-axis space are labelled by joining the axis labels with _, in joint_states order.

julia> b = FiniteBelief([:low, :high], [3 // 5, 2 // 5]);

julia> probabilities(b)
2-element Vector{Rational{Int64}}:
 3//5
 2//5

DecisionAnalysis.CredalSet — Type
CredalSet(states, points; atol)
CredalSet(points; atol)
CredalSet(beliefs::AbstractVector{<:FiniteBelief})

A closed convex set of probability vectors over labelled states, given by a finite list of generating points; the set is their convex hull. The points are meant to be the extreme points, but a redundant generator (one inside the hull of the others) changes no result. Each point is checked like a FiniteBelief.

Γ-maximin, maximality and interval dominance need only these points. E-admissibility does not: an action can be optimal at an interior prior and at no generator, so EAdmissible solves a linear programme over the hull.

julia> c = CredalSet([:low, :high], [[1 // 2, 1 // 2], [1 // 4, 3 // 4]]);

julia> length(extreme_points(c))
2

DecisionAnalysis.ScenarioSet — Type

A set of states held to be possible, with no probabilities attached. State-wise aggregators (WorstCase, BestCase, Hurwicz, Laplace) and regret range over exactly these states; an expectation over a scenario set throws BeliefFormError.

DecisionAnalysis.SampleBelief — Type
SampleBelief(draws; weights=nothing, labels=nothing)
SampleBelief(n::Integer; weights=nothing, labels=nothing)

A belief held as a sample: draws is a Tables.jl table with one row per draw and one column per named parameter (a named tuple of vectors, a vector of named tuples, a data frame), and weights gives each draw's weight. The states of the belief are the draws, so a PayoffTable used with it has one column per draw, in row order. The second form is a sample of n draws with no recorded parameters.

  • weights: nothing (equal weights, the exact 1 // n), a vector of nonnegative numbers, or the name of a column of draws that holds them (the column is then taken out of the parameters). Weights are normalised to sum to one: exactly for integer or rational weights, in floating point otherwise. A negative or non-finite weight, or weights that sum to zero, throw InvalidBeliefError.
  • labels: the state labels of the draws: nothing (:s1, :s2, ..., the default state labels of a payoff table), a vector, or the name of a column of draws that identifies them (taken out of the parameters).

What a sample supports. A sample is a single prior, the weighted empirical distribution of the draws, so Expectation, CVaR, Quantile, regret, evpi and evppi by partition apply to it as they do to a FiniteBelief, and they are estimates of the quantities for the distribution the draws came from. WorstCase, BestCase and Hurwicz range over the draws that happen to be in the sample; the results of rules built on them say so (details.sample_dependent), because a larger sample can only make the worst case worse. Operations that have no meaning for a sample throw BeliefFormError: Laplace (an unweighted mean over draws ignores the weights; use the expectation), total_variation, bayes_invert and the certificate exports (a certificate states exact numbers for a finite problem; convert with FiniteBelief(sample) if the draws are the whole population and not a sample of it).

The estimators with standard errors are evpi, evppi and evsi called with a method (SampleAverage, SplineRegression, ...). See also parameter_draws, draw_weights and effective_sample_size.

julia> b = SampleBelief((; growth=[0.1, 0.3, 0.2], weight=[1, 1, 2]); weights=:weight);

julia> probabilities(b)
3-element Vector{Rational{Int64}}:
 1//4
 1//4
 1//2

julia> effective_sample_size(b)
8//3

DecisionAnalysis.effective_sample_size — Function
effective_sample_size(b::SampleBelief)
effective_sample_size(weights::AbstractVector)

Kish's effective sample size of a weighted sample, (Σ w)² / Σ w²: the number of equally weighted draws that would give a mean the same variance. It equals the number of draws for equal weights and falls towards one as the weights concentrate.

Payoff tables and problems

DecisionAnalysis.PayoffTable — Type
PayoffTable(actions, states, Q; standard_errors=nothing, replicates=nothing)
PayoffTable(Q; actions, states, standard_errors=nothing, replicates=nothing)

The payoff table of a decision problem: Q[a, θ] is the conditional expected utility of action a in state θ, with rows indexed by actions and columns by states (symbols or strings; defaults :a1, :a2, ... and :s1, :s2, ...). Higher is better; costs enter as negative payoffs.

The element type is generic, so a table of Rational{BigInt} is analysed exactly. standard_errors, when given, is a matrix of the same size holding the Monte Carlo standard error of each cell (a stochastic simulator must be averaged inside each cell); it is carried along and never folded into a payoff. replicates, when given, is a matrix of the same size holding the number of simulator runs averaged in each cell. A table with a cell built from one run is flagged (single_replicate): its cells are single outcomes, not conditional expectations, its standard errors are unknown, and both the best reported value and the value with information computed from it are biased upwards by the noise. payoff_table fills both fields from an OutcomeTable.

Throws InvalidPayoffError for an empty table, a non-finite entry, or sizes that do not match the labels. The matrix is copied.

Arithmetic. Tables with the same action and state labels, in the same order, can be added and subtracted (t + u, t - u, -t), and a table can be multiplied or divided by a number (c * t, t * c, t / c); the result is a PayoffTable with the same labels, and mismatched labels throw LabelMismatchError. This is how a utility is assembled from tables of outcome counts: see combine_payoffs, individuals_payoff and infection_payoff. Standard errors are not carried through a sum or a difference (the error of a sum depends on how the cells were simulated); a multiple keeps them, scaled. Replicate counts follow the same rule.

Display. A table prints as a grid of actions against states; in a notebook or a Quarto document it renders as a Markdown or HTML table.

julia> t = PayoffTable([:wait, :act], [:low, :high], [0 -100; -30 -30]);

julia> size(t)
(2, 2)

DecisionAnalysis.combine_payoffs — Function
combine_payoffs(terms::Pair{<:PayoffTable,<:Real}...) -> PayoffTable

The weighted sum of payoff tables with the same labels: combine_payoffs(t1 => w1, t2 => w2, ...) is the table w1 · t1 + w2 · t2 + .... It is the way to build a utility from tables of outcome counts without assembling the matrix by hand; a negative weight makes an outcome a cost. The element type follows the tables and the weights, so rational tables with rational or integer weights stay exact. Mismatched labels throw LabelMismatchError.

julia> uninfected = PayoffTable([:nothing, :treat], [:absent, :present], [500 100; 470 250]);

julia> infected = PayoffTable([:nothing, :treat], [:absent, :present], [0 250; 0 120]);

julia> combine_payoffs(uninfected => 1, infected => -1 // 2).Q
2×2 Matrix{Rational{Int64}}:
 500  -25
 470  190

DecisionAnalysis.individuals_payoff — Function
individuals_payoff(counts::PayoffTable) -> PayoffTable
individuals_payoff(outcomes, name) -> PayoffTable
individuals_payoff(outcomes::OutcomeTable, name) -> PayoffTable

The utility that counts individuals: the payoff of an action in a state is the (expected) number of individuals of the focal population, so the payoff table is the table of counts itself, checked to be nonnegative (InvalidPayoffError otherwise). Expected utility is then an expected number of individuals, and every value of information is read in individuals.

The second form picks the table called name from outcomes, a named collection of outcome count tables: a named tuple, a dictionary, or a vector of name => table pairs. The third applies IndividualsUtility to an OutcomeTable (see payoff_table); all three share one implementation of the utility.

julia> counts = PayoffTable([:nothing, :fence], [:dry, :wet], [40 90; 60 85]);

julia> individuals_payoff((; toadlets=counts), :toadlets) == counts
true

DecisionAnalysis.infection_payoff — Function
infection_payoff(; uninfected::PayoffTable, infected::PayoffTable, weight=1)
infection_payoff(outcomes; uninfected=:uninfected, infected=:infected, weight=1)
infection_payoff(outcomes::OutcomeTable; uninfected=:uninfected, infected=:infected,
                 weight=1)

The utility for an infectious disease, from two tables of counts with the same labels:

payoff = uninfected − weight × infected.

Uninfected individuals count for one each and every infected individual counts against, with weight ≥ 0 the one free parameter: weight = 0 counts only the uninfected, and weight = 1 sets an infected individual against an uninfected one. The weight is a value judgement, so show results at 0, at 1, and as a sweep. Whether infected but living individuals also count towards the population is a modelling choice made when the count tables are built, not here.

The second form takes a named collection of outcome count tables (a named tuple, a dictionary, or name => table pairs) and the names of the two tables in it. The third applies InfectionUtility to the runs of an OutcomeTable and averages inside each cell (see payoff_table); the utility is the same object in all three.

Both counts must be nonnegative (InvalidPayoffError otherwise) and share their labels (LabelMismatchError otherwise); a negative weight is an ArgumentError. The result is exact for exact counts and an exact weight.

julia> uninfected = PayoffTable([:nothing, :treat], [:absent, :present], [500 100; 470 250]);

julia> infected = PayoffTable([:nothing, :treat], [:absent, :present], [0 250; 0 120]);

julia> infection_payoff(; uninfected, infected).Q
2×2 Matrix{Int64}:
 500  -150
 470   130

julia> infection_payoff((; uninfected, infected); weight=0) == uninfected
true

DecisionAnalysis.DecisionProblem — Type
DecisionProblem(payoff::PayoffTable, belief; feasible=nothing, baseline=nothing)
DecisionProblem(payoff::PayoffTable, probabilities::AbstractVector; feasible=nothing,
                baseline=nothing)

A decision problem under uncertainty: choose a row of payoff given belief about its columns. belief is a PointBelief, a FiniteBelief, a SampleBelief, a CredalSet or a ScenarioSet; a plain probability vector is read as a FiniteBelief over the states of the table.

The states of a FiniteBelief, SampleBelief or CredalSet must equal the states of the table, in order; the state of a PointBelief and the states of a ScenarioSet must be among them. A mismatch throws LabelMismatchError.

feasible filters the actions: nothing keeps all, a Bool vector keeps the rows marked true, a collection of labels keeps those actions, and a function is called on each action label. Infeasible actions are ignored by everything: they receive no score, cannot be chosen, and do not enter regret or any value of information. A filter that leaves no action throws NoFeasibleActionError.

baseline names the action that stands for no intervention (business as usual), so that every analysis can be read against it: see gain_over_baseline and expected_gain_over_baseline, and the baseline section of a DecisionReport. It must be one of the actions of the table, otherwise InvalidBaselineError is thrown; it need not be feasible (business as usual may be what is no longer allowed). Setting a baseline changes no score, no choice and no value of information.

julia> t = PayoffTable([:wait, :act], [:low, :high], [0 -100; -30 -30]);

julia> p = DecisionProblem(t, [3 // 5, 2 // 5]);

julia> first_choice(decide(p, MaxExpectedUtility()))
:act

DecisionAnalysis.gain_over_baseline — Function
gain_over_baseline(p::DecisionProblem) -> PayoffTable

The payoff table of differences from the baseline action, G[a, θ] = Q[a, θ] − Q[baseline, θ], for the feasible actions: what each action gains over no intervention in each state. The element type is that of the payoffs, so rational tables stay exact; standard errors are not carried over, because the error of a difference depends on how the cells were simulated. The row of the baseline, when it is feasible, is zero.

Subtracting the same number from every action in a state changes no regret, no Bayes action and no value of information, so a problem restated in gains over the baseline has the same regret_table, evpi and evsi.

Throws MissingBaselineError when the problem has no baseline.

julia> t = PayoffTable([:wait, :act], [:low, :high], [0 -100; -30 -30]);

julia> p = DecisionProblem(t, [3 // 5, 2 // 5]; baseline=:wait);

julia> gain_over_baseline(p).Q
2×2 Matrix{Int64}:
   0   0
 -30  70

julia> expected_gain_over_baseline(p)
2-element Vector{Rational{Int64}}:
  0
 10
source
DecisionAnalysis.expected_gain_over_baseline — Function
expected_gain_over_baseline(p::DecisionProblem)

The gain of every feasible action over the baseline action (no intervention), in feasible_actions order. What is returned depends on the belief.

  • A single prior (FiniteBelief, SampleBelief or PointBelief): a vector, the expected gain Σ_θ p(θ) (Q[a, θ] − Q[baseline, θ]) of each action, which is its expected utility minus that of no intervention.
  • A CredalSet: a named tuple (lower = ..., upper = ...) of two vectors, the smallest and the largest expected gain of each action over the set. The expected gain is linear in the prior, so both are attained at generating points. The two ends are in general attained at different priors for different actions; lower[a] > 0 says that a beats the baseline under every prior in the set.
  • A ScenarioSet: a named tuple (lower = ..., upper = ...) of the minimum and the maximum of the gain Q[a, θ] − Q[baseline, θ] over the states of the set. No probabilities are involved, so these are gains, not expected gains.

The row of the baseline, when it is feasible, is zero in every case. Throws MissingBaselineError when the problem has no baseline.

julia> t = PayoffTable([:wait, :act], [:low, :high], [0 -100; -30 -30]);

julia> credal = CredalSet([:low, :high], [[3 // 5, 2 // 5], [9 // 10, 1 // 10]]);

julia> expected_gain_over_baseline(DecisionProblem(t, credal; baseline=:wait))
(lower = Rational{Int64}[0, -20], upper = Rational{Int64}[0, 10])

DecisionAnalysis.single_replicate — Function
single_replicate(t::PayoffTable) -> Bool

Whether some cell of the table was built from a single simulator run (its replicates entry is one). Such a cell is one outcome, not a conditional expected utility: every maximum over actions then picks up simulation noise, so the act-now value, the value with perfect information and the value with any information are each biased upwards, and the chosen action is on average worth less than its reported score. evpi is a difference of two such terms, so the sign of its bias is not determined. false for a table with no replicate counts, which is taken to hold exact conditional expectations.

source
single_replicate(t::OutcomeTable) -> Bool

Whether some action and draw of the table have exactly one usable run (replicate_counts), so that the payoff table made from it would be flagged (single_replicate(payoff_table(t, utility))): such a cell is one outcome of the model, not a conditional expectation, and has no standard error.
