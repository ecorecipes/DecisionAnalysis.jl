Motivation

A decision analysis ends in comparisons: this action is better than that one, this survey is worth more than it costs. In floating point a comparison between two nearly equal numbers can come out either way. DecisionAnalysis.jl avoids the question for finite problems: give it integers and rationals and every number it returns is an exact rational, every tie is a true tie, and every linear programme is solved exactly.

Exact results can also be checked. The package writes a problem and the numbers it claims for it as a certificate, a small JSON file, and a separate program recomputes the claims. The checker in proofs/ is written in Lean 4, shares no code with the Julia package, and comes with machine-checked proofs that what it accepts is correct. This vignette writes the three kinds of file and checks them.

The problem

The frog pond with Bd, as in the earlier vignettes: three states, three actions, and utility equal to uninfected frogs minus w times infected frogs. Infected but living frogs are not counted as population. The certificate below is for w = 1, and a second one is written for w = 0.

All numbers are illustrative, not data.

using DecisionAnalysis
using Random
include(joinpath("..", "_common.jl"))

actions = [:no_intervention, :antifungal_baths, :disinfect_pond]
states = [:absent, :low_prevalence, :high_prevalence]
uninfected = PayoffTable(actions, states, [500 300 100; 470 380 250; 350 340 320])
infected = PayoffTable(actions, states, [0 150 250; 0 60 120; 0 10 20])
prior = FiniteBelief(states, [1 // 2, 3 // 10, 1 // 5])

function bd_problem(w)
    return DecisionProblem(infection_payoff(; uninfected, infected, weight=w), prior;
                           baseline=:no_intervention)
end

problem = bd_problem(1)
swab = Experiment([19//20 2//5 1//20; 1//20 3//5 19//20];
                  signals=[:negative, :positive], states=states)
problem.payoff

The same problem in floating point gives floating-point answers that agree to rounding error, which is what one wants for large problems. The exact form is for the cases where the comparison itself is the result.

float_problem = DecisionProblem(PayoffTable(actions, states,
                                            Float64.(problem.payoff.Q)),
                                Float64.(probabilities(prior));
                                baseline=:no_intervention)
float_swab = Experiment(Float64.(swab.likelihood); states=states)

Ties are exact

At what weight w do the baths and disinfection have the same expected utility? The expected counts are 399 uninfected and 42 infected for the baths, 341 and 7 for disinfection, so the two are level when 399 − 42w = 341 − 7w, at w = 58/35.

tie = decide(bd_problem(58 // 35), MaxExpectedUtility())
tie.chosen, first_choice(tie), exact.(tie.scores)
([:antifungal_baths, :disinfect_pond], :antifungal_baths, ["1418/7", "1647/5", "1647/5"])

Both actions are returned, and the first choice is the one that comes first in the table. In floating point the same weight does not give a tie unless a tolerance is allowed for, which decide does by default for floating-point problems (rtol).

w = 58 / 35
float_tie = DecisionProblem(infection_payoff(; uninfected, infected, weight=w),
                            Float64.(probabilities(prior)))
decide(float_tie, MaxExpectedUtility(); rtol=0).chosen,
decide(float_tie, MaxExpectedUtility()).chosen
([:antifungal_baths], [:antifungal_baths, :disinfect_pond])

Identities hold exactly

The identities of the earlier vignettes can be tested with == on random rational problems. The package provides generators for that.

rng = Xoshiro(2026)
checks = map(1:200) do _
    p = DecisionProblem(random_payoff_table(rng, 4, 5; T=Rational{Int}),
                        random_belief(rng, 5; T=Rational{Int}))
    e = random_experiment(rng, 3, 5; T=Rational{Int})
    noisy = garble(e, random_experiment(rng, 3, 3; T=Rational{Int}).likelihood)
    return (evpi(p) == minimum(expected_regret(p)),
            0 <= evsi(p, noisy) <= evsi(p, e) <= evpi(p),
            is_garbling_of(noisy, e) !== nothing)
end
md_table(["property, on 200 random rational problems", "holds in all"],

The claims are the expected utility of every action, the value of acting now, the Bayes actions, the regret table with its expected and maximum regret, the minimax-regret actions, EVPI, and with an experiment the value with information and EVSI. The gain over the baseline is not a separate claim: it is the difference of two entries of expected_utility.

A garbling witness

The claim “pooled swabs are a garbling of the swab test” is proved by exhibiting the noise matrix. export_garbling_witness finds it by exact linear programme, checks it in exact arithmetic (nonnegative, columns summing to one, product equal to the garbled likelihood) and writes it.

pooled = garble(swab, [9//10 1//5; 1//10 4//5]; signals=[:negative, :positive])
garbling = joinpath(out, "pooled_is_garbling_of_swab.json")
export_garbling_witness(garbling, pooled, swab)
print(read(garbling, String))

Checking the files with Lean

The Lean project in proofs/ builds an executable, check_certificate, that reads one of these files, recomputes every claim over the rationals, and exits with code 0 when it accepts, 1 when it rejects, and 2 when the file cannot be decoded. It is run as

cd proofs
lake exe cache get                 # once: prebuilt Mathlib
lake build check_certificate       # once
lake exe check_certificate ../vignettes/10_exact_arithmetic_and_certificates/_out/bd_w1.json

The cell below runs the built executable when it is present, and says so when it is not. The output recorded in the rendered copies of this vignette was produced with the executable built.

checker = joinpath(@__DIR__, "..", "..", "proofs", ".lake", "build", "bin",
                   "check_certificate")

function lean_check(file)
    println("check_certificate ", basename(file))
    if !isfile(checker)
        println("  not run: build the checker first (see proofs/README.md)")
        return nothing
    end
    buffer = IOBuffer()
    process = run(pipeline(ignorestatus(`$checker $file`); stdout=buffer, stderr=buffer))
    foreach(line -> println("  ", line), split(chomp(String(take!(buffer))), '\n'))
    println("  exit code: ", process.exitcode)
    return nothing
end

A wrong claim is rejected

text = read(certificate, String)
claimed = "\"evsi\": \"" * exact(evsi(problem, swab)) * "\""
occursin(claimed, text)

tampered = joinpath(out, "bd_w1_tampered.json")

What is and is not certified

An accepted certificate says that the claimed numbers are the correct expected utilities, regrets and values of information for the table, prior and likelihood in the file. It says nothing about whether the table is a good description of the pond. The numbers in this vignette are illustrative, and a certificate of an illustrative table certifies arithmetic about an illustration.

The certificate covers a single prior. The witnesses cover one garbling and one E-admissible action each. Deficiency, robust value of information and the 2 B ε bound are tested in Julia and are not covered by the Lean checker.

What to take away

  • Integer and Rational inputs give exact results: no rounding, true ties, and identities that hold with ==.
  • export_decision_certificate writes a problem and its claimed numbers; export_garbling_witness and export_eadmissible_witness write the witnesses found by linear programme. All three refuse floating-point input, and the witness exporters refuse to write a false claim.
  • lake exe check_certificate FILE.json in proofs/ recomputes a file independently and exits 0, 1 or 2 for accepted, rejected and malformed.
  • A certificate certifies the arithmetic, not the inputs.
